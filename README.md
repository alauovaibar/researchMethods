## 1. Research Overview & Motivation

Retrieval-Augmented Generation (RAG) grounds Large Language Models (LLMs) in external factual evidence to mitigate hallucinations. However, retrieval hyperparameters—notably retrieval depth ($\text{top-}k$) and passage granularity ($\text{chunk\_size}$)—are predominantly configured heuristically without empirical optimization.

This research empirically investigates the joint causal influence of retrieval configuration parameters on the **Hallucination Rate** and **Faithfulness** of open-weight LLMs. By running factorial benchmark experiments, we evaluate whether excessive context introduces distractor noise that degrades generation fidelity, and test whether evidence positioning exhibits the *"Lost in the Middle"* degradation phenomenon.

## 2. Research Questions & Hypotheses

### Research Questions (FINER Framework)
* **RQ1 (Causal):** How does varying retrieval depth $\text{top-}k \in \{1, 3, 5, 10, 20\}$ affect the hallucination rate when generator architecture, retriever, and chunk size are held constant?
* **RQ2 (Optimization / Factorial Interaction):** Which combination of passage $\text{chunk\_size} \in \{128, 256, 512, 1024\}$ and $\text{top-}k$ minimizes the hallucination rate under a bounded context window ($8,192$ tokens)?
* **RQ3 (Position Moderation):** Does the hallucination rate depend on the rank position (first, middle, or last) of the gold evidence passage within the retrieved context?

### Formal Statistical Hypotheses
* **Null Hypothesis ($H_0$):**  
  The mean hallucination rate ($\mu$) across answers generated by the RAG system is invariant across retrieval depth levels ($top\text{-}k$) and chunk sizes:
  $$\mu_{k=1} = \mu_{k=3} = \mu_{k=5} = \mu_{k=10} = \mu_{k=20} \quad (\alpha = 0.05)$$
* **Alternative Hypothesis ($H_1$):**  
  A statistically significant non-linear (U-shaped) relationship exists between retrieval parameters and hallucination rate: insufficient retrieval ($k=1$) leads to hallucinations due to evidence sparsity, an intermediate configuration ($k \in [3, 5]$, $\text{chunk\_size} \approx 256\text{--}512$) achieves minimal hallucination, and excessive depth ($k \ge 10$) causes elevated hallucinations driven by distractor passage noise and context dilution.

## 3. Variables & Metrics Matrix

| Category | Variable | Type / Range | Role & Description |
| :--- | :--- | :--- | :--- |
| **Independent (IV)** | `top_k` | Discrete: $\{1, 3, 5, 10, 20\}$ | Retrieval depth: number of passages fetched from vector index. |
| **Independent (IV)** | `chunk_size` | Discrete: $\{128, 256, 512, 1024\}$ tokens | Corpus indexing granularity with fixed $10\%$ overlap. |
| **Independent (IV)** | `gold_passage_position`| Categorical: `{first, middle, last, auto}` | Placement of gold evidence for testing attention degradation. |
| **Dependent (DV)** | `Hallucination Rate` | Continuous: $[0.0, 1.0]$ | **Primary Metric:** Share of answer claims unsupported by retrieved context. |
| **Dependent (DV)** | `Faithfulness Score` | Continuous: $[0.0, 1.0]$ | **Primary Metric:** RAGAs standard factuality grounding score ($1.0 - HR$). |
| **Dependent (DV)** | `Token F1 / EM` | Continuous / Binary | Lexical overlap and exact match with gold reference answers. |
| **Dependent (DV)** | `Latency (ms)` | Continuous ($> 0\text{ ms}$) | Total end-to-end query time (retrieval + LLM inference). |
| **Controlled (CV)** | Generative LLM | Fixed: `Llama-3-8B-Instruct` | Deterministic greedy decoding (`temperature = 0.0`, `top_p = 1.0`, `seed = 42`). |
| **Controlled (CV)** | Retriever & Metric | Fixed: Dense Cosine (`dim = 384`)| Standardized embedding space and similarity scoring. |
| **Controlled (CV)** | Prompt Template | Fixed: Strict Factual RAG | Explicit directive to answer solely using supplied evidence. |
| **Controlled (CV)** | Environment | Fixed: `Python 3.12.10-slim` | 100% pinned package dependencies via Docker and requirements. |

### Operational Guardrail Thresholds
* **$P95\ \text{Latency} \le 2,500\text{ ms}$:** Interactive user-facing latency constraint.
* **$\text{Max Context Window} \le 8,192\text{ tokens}$:** Bounded LLM attention capacity.
* **$\text{Pipeline Error Rate} = 0.00\%$:** Zero unhandled runtime exceptions.
* **$\text{Max RAM} \le 4,096\text{ MB}$:** Safe deployment memory profile.

### Baseline Definitions
* **Baseline 0 (Zero-shot / No-RAG, $k=0$):** Parametric memory baseline without context retrieval.
* **Baseline 1 (Standard Vanilla RAG):** Fixed industry default ($top\_k = 3$, $chunk\_size = 256$, auto positioning).

## 7. Quickstart Guide (Run in 2–3 Commands)

### Option A: Native Python (Fastest)

```bash
# 1. Install pinned dependencies
pip install -r requirements.txt

# 2. Run unit tests
pytest -v tests/

# 3. Execute the benchmark on sample data
python src/benchmark.py --config configs/config.yaml
```

To run the complete **factorial sweep** across parameter combinations:
```bash
python src/benchmark.py --config configs/config.yaml --sweep
```

### Option B: Using Shell / PowerShell Scripts

* **Linux / macOS:**
  ```bash
  chmod +x scripts/run_benchmark.sh
  ./scripts/run_benchmark.sh
  ```
* **Windows (PowerShell):**
  ```powershell
  .\scripts\run_benchmark.ps1
  ```

### Option C: Docker Container (100% Isolated & Reproducible)

```bash
# 1. Build the container image
docker build -t rag-benchmark:latest .

# 2. Run the benchmark inside the container
docker run --rm -v $(pwd)/results:/app/results rag-benchmark:latest

# 3. Run factorial sweep inside the container
docker run --rm -v $(pwd)/results:/app/results rag-benchmark:latest --sweep
```
